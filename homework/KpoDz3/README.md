```markdown
# Архитектура микросервисов

Проект состоит из трёх микросервисов:

- **Analysis Service (Аналитики)**:  
  Проверяет файлы на плагиат и формирует/обновляет базу данных студентов и отпечатков файлов.  

- **Storage Service (Хранения)**:  
  Сохраняет файлы в S3-совместимом хранилище MinIO и предоставляет временные ссылки для скачивания.  

- **GateWay**:  
  Перенаправляет все пользовательские запросы к другим сервисам, преобразуя их при необходимости.
```

```markdown
## Сценарии использования текстом

### Студент
1. Отправляет multipart form с файлом задания, именем студента и номером работы в GateWay.  
2. GateWay генерирует уникальное имя файла и пересылает файл и имя в Storage Service.  
3. Storage Service сохраняет файл в MinIO и возвращает подтверждение.  
4. GateWay отправляет JSON с именем студента, новым именем файла и номером работы в Analysis Service.  
5. Analysis Service делает GET запрос к Storage Service для получения временной ссылки на файл.  
6. Сервис скачивает файл (не хранит его), проверяет на плагиат и обновляет таблицы базы данных (отпечаток и студент).  

### Преподаватель
1. Отправляет GET запрос с номером задания в GateWay.  
2. GateWay перенаправляет запрос в Analysis Service.  
3. Analysis Service формирует список всех работ по номеру задания и возвращает результат через GateWay преподавателю.  
```
```markdown
## Примечания
- Все внутренние обращения между сервисами используют DNS-имена контейнеров (`storage-service`, `analysis-service`).  
- GateWay является единой точкой входа для клиентов (студентов и преподавателей).  
- Storage Service не хранит метаданные студентов или работы — это задача Analysis Service.
```
