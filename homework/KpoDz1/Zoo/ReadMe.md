Для запуска приложенияв корневой папке необходимо собрать приложение через 
```./gradlew clean build``` и запустить его.
Или использовать
```./gradlew run --console=plain```,
чтобы запустить в режими менеджера gradle

Для запуска тестов нужно прописать 
```./gradlew test```


Принципы SOLID:
```markdown
1. Single Responsibility Principle (Принцип единственной ответственности)
Каждый класс выполняет только свою задачу:
ZooService: Управляет логикой зоопарка.
ConsoleUI: Отвечает за работу UI.
VetClinicService: Отвечает за проверку здоровья животных.
```
```markdown
2. Open/Closed Principle (Принцип открытости/закрытости)
Интерфейсы IAlive, IClinic, IInventory позволяют менять конкретные реализации не меняя основные сервисы.
```
```markdown
3. Liskov Substitution Principle (Принцип подстановки Барбары Лисков)
В списках List<Animal> могут находиться и Tiger, и Rabbit.
Метод getAllFood() корректно вызывает getFood() у любого объекта, независимо от его конкретного типа.
и тд.
```
```markdown
4. Interface Segregation Principle (Принцип разделения интерфейса)
Интерфейсы разделены по смыслу, чтобы классы не реализовывали лишние методы:
IAlive: Методы живых существа.
IInventory: Методы инвентаря.
```
```markdown
5. Dependency Inversion Principle (Принцип инверсии зависимостей)
Классы зависят от абстракций, а не от конкретных реализаций:
ZooService зависит от интерфейса IClinic, а не от конкретного класса VetClinic.
Внедрение зависимостей (Dependency Injection) реализовано через конструктор.
Все сервисы лежат как бины в DI контейнере
```

Проверена фильтрация животных для "Контактного зоопарка".
